# Как устроены ИИ-системы поддержки: архитектура и принятие решений

> Исследование Alex (deep research, 2026-07-21): 23 источника (Intercom Fin, Sierra, Decagon, NVIDIA NeMo Guardrails, OpenAI Cookbook, Rasa, препринты); 25 ключевых утверждений прошли тройную проверку. Проектный референс kremzaPay-бота. Сохранено из чата, сокращено без потери сути.

## Главные выводы

1. Продакшен-система — **конвейер фаз с проверками**, не «один умный LLM»: уточнение запроса и роутинг → RAG-генерация → валидация ответа (Intercom Fin). На каждой фазе запрос может быть отклонён/перенаправлен/эскалирован.
2. **Специализированные малые модели бьют универсальные LLM в узких задачах**: Intercom дообучил эмбеддер Snowflake Arctic 2 на ~2 млн запросов → precision retrieval 44.79%→74.33%, Recall@5 86.15%→96.59%; решение об эскалации принимает дообученный ModernBERT (3 головы: 3-way решение / причина из 8 / сработавшие гайдлайны), ~90% случаев с точностью >98%, LLM — только сложный хвост (триггер — длина/сложность, не уверенность). Sierra оркестрирует 15+ моделей.
3. **Guardrails — отдельный слой**, 5 типов рельсов (NeMo): input / dialog / retrieval / execution / output; исполняются **асинхронно параллельно** основному вызову (OpenAI Cookbook, Decagon) ради латентности.
4. **Решение «отвечать/эскалировать» — отдельная подсистема**: у Fin неуверенность → просьба уточнить, небезопасность → автоматическая эскалация (разные ветки!). Эскалация — 3-way: немедленно / предложить / продолжать.
5. **У каждой LLM свой врождённый порог эскалации** (препринт HBS/JHU 2026: ~56% у одной модели vs ~91% у другой, не предсказывается размером/семейством) → поведение эскалации своей модели **замеряется эмпирически на eval-сете до деплоя**, а не задаётся промптом.
6. **Честно молчать, а не красиво выдумывать** — все изученные системы при неуверенности уточняют или передают человеку.

## RAG у Fin (3 ступени)

Векторный поиск (~40 кандидатов, скорость) → reranking тяжёлой моделью (топ-5–10) → генерация из отобранного + контекст пользователя. Дообучение retrieval на своих данных — «самая доходная инвестиция пайплайна».

## Классификация (дополнение к 02-classifier-spec)

- Точность выбора сценария LLM-агентом падает с ростом каталога: ~94% @50 → 64% @200 → 13.6% @741. Роутинг-слой — необходимость.
- LLM-классификатор со structured output на ~8 классах: macro-F1 ≈ 0.92–0.96 без обучения → «достаточно хорош» на старте (5–30 интентов).
- Semantic router (эмбеддинги+косинус к эталонам маршрутов) — стандартный дешёвый слой; SetFit — точный классификатор с малым числом примеров.
- Роутинг решает и «какую механику запускать»: детерминированный workflow vs LLM-ответ — часть трафика вообще не доходит до LLM.

## OOS / fallback (эталон Rasa)

FallbackClassifier: уверенность < порога (например 0.7) → спец-интент `nlu_fallback`, не «лучшая догадка» · явный интент out_of_scope на реальных примерах; ожидаемые-но-неподдерживаемые → отдельные интенты с адресными ответами · уверенность диалога отделена от уверенности NLU (второй порог ~0.4) · **Two-Stage Fallback**: переспросить → попросить переформулировать → человек.
Современно: topical guardrail — дешёвый LLM-классификатор allowed/not_allowed со списком разрешённых тем → canned-ответ (OpenAI Cookbook).
Многосигнальность: OOS-класс + порог расстояния + retrieval-сигнал + topical guardrail — любой сигнал уводит с основной ветки.

## Guardrails (NeMo, 5 рельсов)

| Рельс | Стадия | Что может |
|---|---|---|
| Input | до обработки | отклонить/изменить вход (инъекции, токсичность, off-topic) |
| Dialog | ход диалога | допустимые ветки разговора |
| Retrieval | после поиска | отклонить фрагменты базы до передачи в LLM |
| Execution | вызовы инструментов | контроль действий/API |
| Output | перед отправкой | галлюцинации, факт-чекинг, политика |

Decagon, 3 фазы: до деплоя (регрессионное тестирование) · в реальном времени (параллельные дообученные модели + bad-actor detection) · после диалога (Watchtower проверяет **каждый** диалог по настраиваемым критериям).

## Вендоры

- **Intercom Fin** — 3-фазный конвейер, 3-ступенчатый RAG, дообученный retrieval, «энкодер 90% + LLM 10%» на эскалации. Самый прозрачный.
- **Sierra** — «созвездие» 15+ моделей, supervisor-модели, раздельные компоненты (retrieval/классификация/инструменты/политики/тон), failover между провайдерами.
- **Decagon** — Core Agent + Routing Module + Agent Assist (копилот оператора) + Watchtower; «маховик данных»: каждый диалог улучшает систему.

## Open-source стек

NeMo Guardrails (все 5 рельсов) · паттерны OpenAI Cookbook/Agents SDK (async guardrails, topical) · Rasa (FallbackClassifier, Two-Stage Fallback; современный CALM — LLM-генератор команд + детерминированные флоу) · LangGraph (сравнение CALM vs LangGraph: 14/14 e2e, ~$0.031 и ~2.6 с/сообщение) · эмбеддер Snowflake Arctic 2 как стартовый с прицелом на дообучение.

## Рекомендуемая архитектура (синтез)

```
Запрос → [Input guardrails: инъекции/токсичность/PII — асинхронно]
       → [Классификация/роутинг: каскад «правила → эмбеддинги → LLM»;
          детерминированные сценарии — мимо LLM]
       → [OOS/off-topic: явный класс + порог + topical guardrail]
       → [RAG: поиск ~40 → rerank → топ-5-10 → LLM с контекстом]
       → [Output guardrails: groundedness, политика — параллельно]
       → [Решение: certainty → ответить/уточнить; safety/бизнес-триггер → эскалация с контекстом]
       → [Пост-анализ каждого диалога → петля улучшения]
```

Принципы: пороги — по confusion matrix на eval-сете; эскалация модели замеряется эмпирически; неуверенность → уточнение, небезопасность → эскалация; с ростом трафика узкие задачи переводятся на дообученные малые модели.

## Ограничения исследования
